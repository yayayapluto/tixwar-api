# Benchmark war — 300 VU vs 100 tiket

## Command

```bash
# 1. Siapkan token load test dari user hasil seed (300 user)
GEN_TOKEN_USERS=300 bun run scripts/gen-tokens.ts --existing > .tmp/tokens.json
#    lalu tulis accessToken per baris ke .tmp/tokens.txt

# 2. Buat event + tier kuota 100 (maxPerUser=1) lewat admin API, lalu prewarm stok
bun run scripts/rebuild-stock.ts --apply

# 3. Jalankan war
k6 run load/war.js \
  --env BASE_URL=http://127.0.0.1:3000 \
  --env TIER_ID=<tier_id> \
  --env TOKENS_FILE=../.tmp/tokens.txt \
  --env VUS=300 \
  --env RAMP_UP=20s \
  --env HOLD=40s
```

## Catatan

- `http_req_failed` pada skenario ini memakai `http.setResponseCallback(http.expectedStatuses(201, 409, 429))`; 409 `SOLD_OUT` adalah hasil yang diharapkan pada war, bukan kegagalan. Sebelum callback ini ditambahkan, run pertama mencatat 99,28% "failed" yang sebenarnya adalah 409.
- Latensi p95 1,44 s muncul karena semua VU menyerbu tier yang sama; jalur panasnya adalah `findOne` tier/event + Lua reserve + transaksi Mongo + outbox insert. Angka ini bukan target produksi, melainkan catatan environment demo.
- Stok di-prewarm lewat `scripts/rebuild-stock.ts --apply` karena tier dibuat setelah proses API berjalan; `prewarmDueTiers` hanya mengisi tier yang belum punya key dalam jendela 5 menit sebelum sale.

# Benchmark browse — 50 VU, 30 detik (cache hangat)

## Command

```bash
k6 run load/browse.js \
  --env BASE_URL=http://127.0.0.1:3000 \
  --env VUS=50 \
  --env DURATION=30s
```

| Item | Nilai |

| MongoDB | 7.0 sharded: 3 config server, 3 shard replica set satu anggota, 1 mongos |
| Redis | 7-alpine, AOF `everysec` |
| Runtime API | Bun 1.3.14, `bun run src/server.ts`, port 3000 langsung (tanpa Nginx) |

| Commit | `a8cbb8c` (dev) |

Threshold yang ditetapkan `load/browse.js`: `p(95) < 300ms` dan `http_req_failed < 1%`. Keduanya lulus.

## Catatan

- Cache list dan detail sudah hangat sebelum run ini (request pemanasan dilakukan oleh `load/smoke.js` dan seed). Angka ini bukan perbandingan sebelum/sesudah cache.
- Setiap iterasi mengirim tiga request: `GET /v1/events?limit=20`, `GET /v1/events?limit=20&city=jakarta&sort=-startsAt`, dan `GET /health`.
- `/health` tidak melewati cache sehingga menurunkan rasio hit agregat; metrik `cache_hits_total{cache="events-list"}` di `/metrics` menunjukkan rasio sebenarnya untuk katalog.
